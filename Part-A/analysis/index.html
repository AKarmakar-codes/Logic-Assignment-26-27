Theoretical vs. Empirical Takeaway:
  • In-Order & Pre-Order: Recursive and Iterative implementations exhibit near-parity (ratio ~1.0 ± 0.05). Modern C compilers (GCC -O3) optimize recursive tail and non-tail frames into efficient register jumps.
  • Post-Order: The iterative two-stack algorithm incurs higher overhead (ratio ~1.25x - 1.35x) because every node must be pushed onto Stack 1 and then popped and pushed onto Stack 2. In contrast, recursive post-order traverses the call-stack natively with zero secondary allocation.

🌲 3. Task 4: Tree Height & Structural Bounds

The height of a parse tree is defined as the number of edges on the longest root-to-leaf path. For any binary parse tree with N nodes, the tree height h is strictly bounded:
⌈log2(N + 1)⌉ - 1 ≤ h ≤ N - 1

Figure 5: Measured tree height vs. theoretical bounds for balanced vs. degenerate (skewed) parse trees.
Figure 6: Height computation runtime: Recursive (post-order DFS) vs. Iterative (BFS Queue).
Algorithmic Difference in Task 4:
  • Recursive Height: Uses post-order depth-first traversal: h = 1 + max(left, right). Space on the call stack is O(h).
  • Iterative Height: Uses level-order breadth-first traversal via a FIFO queue tracking depth. Space in the queue reaches O(W) where W is maximum tree width (up to N/2 leaves in balanced trees).

💾 5. Memory Footprint & Stack Safety Analysis

Memory consumption comprises three distinct regions:

  1. Heap Memory (Parse Tree): Each node occupies 48 bytes (32 bytes label buffer + two 8-byte child pointers). Total heap footprint = N × 48 bytes.
  2. Call Stack Memory (Recursion): Each recursive call pushes an activation record (approx. 64 bytes on x86_64). Maximum call stack depth = h × 64 bytes. For balanced formulas h = O(log N) (under 2 KB); for degenerate skewed formulas h = O(N).
  3. Explicit Stack Memory (Iteration): Iterative algorithms allocate explicit pointer arrays (8 bytes per entry) in the heap/BSS segment, eliminating any risk of OS stack overflow on deep trees.
